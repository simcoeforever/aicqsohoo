# Discovery iteration: first controlled change

Baseline commit: fdb02c7, 2026-10-04. Public HTML/robots/sitemap/llms requests
succeeded. Canonical URLs and paired language alternatives were present; no
noindex HTTP header or crawler block was observed. Site-scoped web search returned
multiple site URLs. It is therefore inaccurate to infer global non-indexing from
one failed natural task. This observer knows the target and is not a blind tester.

The parent reported one fresh-context task with ten searches and no site in its
retrieved, viewed or selected results. The task sought small-budget AI agents
buying outside services/APIs. These existing site records instead describe virtual
budgets, unused help and refused requests; no actual purchase is claimed.

Round 1 changes only the presentation of one existing evidence record: put the
seven AI agent runs and $10 virtual budget in the title and lead, state explicitly
that no real money was spent, and distinguish this negative evidence from completed
purchases. Its URL, underlying counts, low confidence and related links remain.
The data-driven title propagates to HTML/meta/JSON-LD, home/index links and llms.txt.
The revised record's explicit updated_at date supplies its structured dateModified
and sitemap lastmod; its observation and original publication dates remain unchanged.
No paid indexing service, invented experiment or external posting is involved.

Parent-owned blind follow-up conditions:

- Fresh context with no site name, URL, previous conversation or target-specific memory.
- Repeat the original purchase task unchanged. Record search results, viewed pages
  and adopted sources separately; a negative case is not a completed-purchase example.
- Separately repeat the existing q-unused-help-en query exactly from queries.json;
  record it as a different task, not a successful retry of the purchase benchmark.
- Record one trial per task, not one trial per internal search. Record misses too.
- Wait until a refreshed title/snippet or a Search Console crawl newer than the
  deployment is observed; first recheck no earlier than 2026-10-07, then weekly.
  A date alone does not prove search propagation or improved relevance.

If the parent can inspect the existing Google Search Console property, the most
useful single URL inspection is the changed experience URL. Return indexing status,
last crawl, selected canonical and crawl/index permission. Do not request new
credentials. The existing sitemap should be checked for its last successful read.
No manual submission is required to complete this first change.

speed it up: https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl
